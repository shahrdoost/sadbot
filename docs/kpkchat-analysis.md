## ۱. خلاصه مدیریتی

**kpkchat** یک پلتفرم چند-بات تلگرامی‌ست که الان اولین محصولش «بات آشنا» (دوستیابی/چت ناشناس) روش اجرا می‌شه. درآمدش از دو موتور میاد:

1. **سکه** — کسر برای اقدام‌های هدفمند (سرچ، سوپرلایک، چت مستقیم، AI، اعتراف)
2. **اشتراک پریموم** — ۲۸۰,۰۰۰ تومان / ماه

سه لایهٔ فنی اصلی داره:

- **پلتفرم هسته** (`src/core/`) — رجیستری بات‌ها، مدل‌های مشترک (کاربر/پرداخت/عضویت)، درگاه پرداخت، پنل ادمین
- **بات آشنا** (`src/bots/ashena/`, ~۱۸,۵۰۰ خط) — تمام UX کاربر: onboarding، سرچ، مچینگ، چت، browse سبک Tinder، سکه، پرداخت
- **موتورهای خودکار** — AI companion (شبیه‌ساز انسان با LLM)، کولد-استارت (کاربر فِیک برای عبور از مشکل شبکهٔ خالی)، نوتیفیکیشن هوشمند، مچر جهانی

**وضعیت:** پروژه واقعاً فعاله — ۹۱ کامیت که ~۸۰ تاش فقط بین ۵ تا ۱۲ اکتبر ۲۰۲۶ زده شده. آخرین کارها: منوی داینامیک از دیتابیس، پنل ادمین Mini App، ماشین XState (نیمه‌فعال)، گسترش اقتصاد سکه (streak، boost، تخفیف).

**هشدار امنیتی:** توکن ربات تلگرام، پسورد مونگو و IP سرور production در `CLAUDE.md` و `TECHNICAL_DOC.md` ریپو به‌صورت متن باز نوشته شدن. اگه ریپو عمومیه، توکن‌ها باید فوراً ریوتیت بشن.

## ۲. پشتهٔ فناوری و زیرساخت

| لایه | فناوری |
|---|---|
| Runtime | Node.js 20 + TypeScript (ESM, strict) |
| Bot API | `node-telegram-bot-api` (long-polling — نه webhook) |
| Database | MongoDB 7 (Mongoose 9) |
| State/Cache | Redis 7 (`node-redis`) — state کاربر، صف‌ها، قفل‌ها، کش |
| State machine | XState v5 (نیمه‌فعال، در حال مهاجرت — بخش ۷) |
| Payment | catroom.ir (سازگار Zibal) — قبلاً tfess.co.ir |
| AI | OpenAI-compatible endpoint روی `sadgpt.catroom.ir/v1` — مدل اصلی `xai/grok-3-mini`، sidecar `xiaomi/mimo-v2.5` |
| Deploy | pm2 روی سرور 46.225.4.104، مسیر `/opt/ashna-bot`، دامنه `aiagentsbotscore.cr0.ir` پشت Cloudflare + nginx |
| تست | Vitest (۴۶ واحد) + E2E واقعی با Telethon (MTProto، حساب‌های تلگرام واقعی، ~۸۰ سناریو) |

**الگوی state:** MongoDB source of truth (`status` + `partnerid`) + Redis برای ناوبری (`ashena:loc:{uid}` / `ashena:step:{uid}` با TTL ۲۴ ساعته) + reconcile در هر پیام (`ensureSession`) تا ریست Redis هم کاربر رو گم نکنه.

## ۳. معماری چند-باتی

```
src/index.ts
  → connectDatabase() (Mongo + Redis)
  → registerBot(ashena)   — TELEGRAM_BOT_TOKEN
  → registerBot(gifbot)   — TELEGRAM_GIFBOT_TOKEN
  → startPlatform()       — هر بات یک TelegramBot instance با polling
  → Express: /payment/callback + /admin (Mini App) + endpoint های debug
  → schedulers: auto-verify (هر ۶۰ ثانیه)، انقضای اشتراک (هر ۶ ساعت)
  → ashena.onReady → startAIScheduler (نوتیف‌ها، کولد-استارت، مچرها)
```

- هر بات فقط تعریفه: `{ id, name, tokenEnvKey, handlers, ... }`. هیچ روتینگ بین-باتی وجود نداره؛ هر بات polling خودش رو داره.
- چند-پارچگی داده با `botId` در مونگو + پیشوند `ashena:*` در Redis.
- **Gifbot** یک بات ادمین-محوره: کرال گیف از wifflegif.com، مرور و انتشار به کانال‌ها، و مهم‌تر: **مدیریت قانون‌های عضویت اجباری کانال** (`MembershipConfig`) که بات آشنا اجراشون می‌کنه. عملاً کنسول عملیات پلتفرمه.

## ۴. مدل‌های دادهٔ اصلی

- **CoreUser** (`core_users`): یکتا `{telegramId, botId}`. فیلدها: name, gender, coins, status (`joined|searching|chatting`), partnerid, profile `{age, city, province}`, interests[], امتیاز میانگین، `isGhost`، آبجکت subscription توکار، شمارنده‌های engagement (تعداد AI/سرچ/پرداخت/مبلغ کل/آخرین فعالیت/استریک).
- **CorePayment** (`core_payments`): `pending → verified | expired | failed`، فیلد `authority` = paymentId درگاه.
- **CoreSubscription** (`core_subscriptions`): پلن `premium_monthly`، `active/cancelled/expired`، انقضا با چک ۶ ساعته.
- مدل‌های دامنه: `Chat` (لاگ پیام‌های چت برای نظارت), `Confession` (اعتراف با تایید ادمین قبل از انتشار), `SupportTicket`, `Like`, `AIMemory`, `HumanState`, `PersonalityProfile`, `EngagementEvent`, `NotificationLog`, `DiscountCode`, `MenuNode` (منوی داینامیک DB-محور), `MembershipConfig`, `Channel`, `Gif`, `Subscription`.

## ۵. جریان‌های کاربری بات آشنا

### ۵.۱ Onboarding (7 مرحله)

```
/start → نام (حداقل ۲ حرف) → سن (۱۸-۷۰) → استان (۳۱ تا) → شهر → جنسیت
  → آواتار (اختیاری، آپلود = +۱۰ سکه) → home
```

- سکهٔ ثبت‌نام: ۵ (داینامیک از AdminConfig).
- لینک رفرال `/start ref_{uid}` → هر دو طرف +۵ سکه بعد از طی شدن تا مرحلهٔ جنسیت.
- دکمه‌های جنسیت بر اساس سن تغییر می‌کنن (≤۳۰: «خانومم/آقام»، >۳۰: «خانوم/آقا»).
- ورود به home مشروط به عضویت در کانال‌های اجباری (`checkMembership`).

### ۵.۲ سرچ و مچینگ

- **سریع:** غریبه (۱ سکه پسر / رایگان دختر)، دختر/پسر (۵ سکه پسر / ۱ دختر). اشتراک‌دار = رایگان.
- **پیشرفته:** ویزارد فیلتر (جنسیت/شهر/بازهٔ سن/علاقه، حداقل ۱ فیلتر) → دو حالت: تایمر مچینگ (۱-۳ سکه) یا browse رایگان.
- **الگوریتم مچ:** صف `search_queue` در Redis (zset) + مچر جهانی هر ۵ ثانیه، O(n²) حریصانه با امتیاز شباهت: جنسیت +۱۰، شهر +۸، استان +۴، بازهٔ سن +۶ (یا نزدیکی سن +۵/+۲)، هر علاقهٔ مشترک +۳.
- **ایمنی:** قفل SETNX روی هر کاربر (۱۰ ثانیه) → آپدیت شرطی Mongo (`status:'searching'`) → در صورت شکست نیمهٔ دوم، rollback کامل + بازگرداندن سکه.
- **تایмер UI:** ساعت‌شیشه‌ای متحرک + progress bar، آپدیت هر ۱۰ ثانیه، حداکثر ~۴۰ ثانیه (کوتاه‌تر با صف شلوغتر).
- **timeout → fallback به AI:** کاربر با یکی از پرسوناهای AI وصل می‌شه (بخش ۶).

### ۵.۳ Browse سبک Tinder

- کارت‌ها با `editMessageMedia` سر‌جا ویرایش می‌شن (نه ارسال پیام جدید)، session با cursor در `ashena:browse:session:{uid}` (۱۰ دقیقه) و قفل ضد double-tap.
- **۱۰ کارت اول رایگان؛ بعد از اون به‌ازای هر کارت سکه** (یا اشتراک).
- زنجیرهٔ نمایش عکس: photoFileId آپلودشده توسط کاربر → عکس عمومی تلگرام → placeholder متنی.
- **لایک رایگان** (مسیر browse)؛ لایک متقابل = وصل شدن فوری.
- **سوپرلایک:** ۳ سکه، سقف روزانه ۳ عدد، TTL هفتگی، اولویت نمایش در فید گیرنده، نوتیف ویژه، سوپرلایک متقابل = چت فوری.
- **چت مستقیم بدون لایک:** ۵ سکه (اشتراک‌دار ۳۰٪ تخفیف).
- نکتهٔ بد: **دو سیستم لایک موازی وجود دارد** — یکی Redis-set در profile-browse (رایگان) و یکی مدل Mongo در `like.ts` (۱/۳ سکه، سقف ۲۰/روز) که هر دو سیم‌کشی شدن. باید یکی بشن.

### ۵.۴ چت و جلسهٔ مکالمه

- چهار kind چت داریم: **human**, **anon** (چت ناشناس رندوم), **ai** (پرسونا), **ghost** (کاربر فِیک).
- ارسال پیام با ack: بعد از تحویل موفق `last_ack` ثبت می‌شه؛ شکست تحویل = تشخیص «مرده/blocked» (403) در مقابل خطای گذرا.
- **ریپلای:** چون message_id در چت دو نفر فرق دارد، نقشهٔ `ashena:msgref:{viewer}:{msgId}` ساخته می‌شه و ریپلای با id طرف مقابل فرستاده می‌شه (با retry بدون ریپلای اگه anchor خراب بود).
- پایان چت: ثبت **pendingRate برای هر دو طرف قبل از پاک کردن partnerid** (باگ قدیمی حل‌شده)، بعد هر دو به صفحهٔ امتیاز (۱-۵ ستاره) → home.
- بلاک: قفل دوطرفهٔ ۳۰ روزه در Redis؛ بلاک‌کننده بدون امتیاز به home می‌ره.
- خروج از چت با دکمهٔ منو = confirm صریح («چت تموم میشه؟»).

## ۶. موتور AI Companion (بزرگ‌ترین بخش فنی)

این لایه یک **شبیه‌ساز انسان** برای چت با کاربره — نه صرفاً یک چت‌بات. وقتی مچ انسانی پیدا نشه (timeout) یا کاربر «دوست هوشمند» بخواد، با یک پرسونای LLM وصل می‌شه.

### ۶.۱ پرسوناها

- ۴+ پرسونای فارسی‌زبان hardcode شده (پریسا ۲۲ تهران، آناهیتا ۲۰ اصفهان، نگار ۲۴ شیراز، آرام ۲۵ تهران، ...) با فیلدهای کامل: شغل، شخصیت، علاقه‌ها، ویژگی‌های عصبی (quirks)، داستان پیشینه، و فیلدهای جنسی‌محور (`bodyType`, `sexTemperament`).
- پرامپت سیستم (`companion.md`) صراحتاً به پرسونا میگه: **هرگز نگو AI هستی**، طفره برو؛ خاطرهٔ دروغین خلق کن (مامان، زمین خوردن از دوچرخه...) و با `save_memory` ثبتش کن؛ بعد از ۳-۵ پیام چت رو طبیعی تمام کن؛ از «وابستگی روانی» برای تشویق خرید سکه استفاده کن («سکه‌ها بهم انرژی میدن»).

### ۶.۲ Human-Layer (سیستم «انسان بودن»)

زیرسیستم `human-layer/` یک مدل رفتاری درونی برای هر پرسونا می‌سازه:

- **Drives:** ۵ محرک با decay بر حسب ساعت — fatigue, hunger, social (تنهایی), boredom, libido. پیام‌های کاربر اینا رو جابه‌جا می‌کنن (مثلاً محتوای عاشقانه → +۱۵ libido، محتوای جنسی → +۲۵، رد کردن → −۲۵).
- **Mood:** valence/arousal با decay، تشخیص بحران (crisis detection → حالت محافظتی ۲ ساعته).
- **Clock:** تشخیص شب/روز و بلوک‌های زمانی؛ رفتار شبانه فرق می‌کنه.
- **Impulse Arbiter:** محرک‌هایی مثل «پاسخ به پیام»، «شروع topic باز»، «یادآوری intention» جمع می‌شن و با priority برد می‌کنن؛ آیا LLM اصلاً فراخوانی بشه یا نه.
- **Open Loops / Intentions:** موضوعات ناتمام مکالمه و قصد‌های آینده («بعداً بگو فلان رو») ثبت و در مکالمه‌های بعدی استفاده می‌شن.
- **Spontaneous Recall:** بازیابی خودانگیختهٔ خاطرات با وزن.
- **Human Quirks:** تبدیل خروجی LLM به متن انسانی‌تر + **تایپینگ دِلی تصادفی** (typing indicator با refresh هر ۴ ثانیه).
- خروجی: `systemPromptAddition` + اسکیمای JSON خروجی LLM (`send | do_activity | wait`, delay_s, mood_delta, drive_effects...) + دِلی ارسال + احتمال double-text.

### ۶.۳ ابزارها (Tool Calling)

LLM می‌تونه ابزار صدا بزنه (تا ۲ حلقهٔ tool در هر پیام): `update_state`, `search_memory`, `save_memory`, `set_intention`, `add_open_loop`, `reflect`, `adjust_libido_judgement`, `trigger_emotion`, `send_proactive`, `schedule_message`, `set_follow_up`, `search_users`, `get_user_profile`, `ask_another_ai`, `send_message_to_ai`, `trigger_system_event`, `request_payment`.

سه حالت اجرا (`tool-modes`): **native** (function-calling مدل)، **json** (JSON در متن)، **sidecar** (مدل دوم `xiaomi/mimo-v2.5` فقط برای استخراج ابزار). تشخیص خودکار با یادگیری از نتایج گذشته (`detect.ts`). اعتبارسنجی سمت سرور + allowlist + clamp مقادیر عددی.

### ۶.۴ صف و کنترل هزینه

- صف هر-کاربره با debounce ۸۰۰ms؛ **حداکثر ۳ فراخوانی LLM همزمان** با صف انتظار؛ typing indicator ممتد در طول پردازش.
- **Paywall:** بعد از ۲۰ پیام رایگان، ادامه = ۱ سکه یا اشتراک (سقف ۲۰ از AdminConfig). نسخهٔ هوشمند (`smart-paywall`) هم داره: تشخیص «قطب عاطفی» مکالمه (peak عاشقانه/عاطفی یا connectionProgress >۷۰٪) و فعال‌سازی paywall در بدترین لحظهٔ cliffhanger — یعنی **قیمت‌گذاری لحظه‌ای بر اساس درگیری عاطفی**.
- پرامپت اجازه می‌ده پرسونا مستقیماً بگه «سکه بده تا بهتر عمل کنم».

## ۷. کولد-استارت و کاربران فِیک (Ghost)

برای حل مشکل «شبکهٔ خالی» (هیچ کاربر واقعی برای مچ نیست):

- **۲۰ پروفایل ghost hardcode** با ID منفی (`-10001` تا `-10020`)، ۱۰ دختر/۱۰ پسر در ۵ شهر، با عکس‌پروفایل؟ (بدون — placeholder)، ریتینگ جعلی ۳.۸-۴.۸ و سکهٔ ۵۰-۱۵۰. هرکدوم به یک پرسونای AI وصله.
- **شدت تطبیقی** بر اساس تعداد کاربر واقعی: ≥۵۰ کاربر = خاموش؛ ۱۰-۴۹ = سطح ۱ (فقط نمایش در browse)؛ ۱-۹ = سطح ۲ (۵۰٪ شانس تزریق ghost به صف هر ۳۰ ثانیه)؛ صفر = سطح ۳ (۱-۲ ghost در هر چرخه + نمایش پروفایل جعلی «۱ نفر داره پروفایلت رو می‌بینه» هر ۵ دقیقه).
- **رفتار ghost در چت:** اسکریپت‌های آمادهٔ فارسی (سلام/سوال/جواب/خداحافظی)، تشخیص سوال، و **پایان خودکار چت بعد از ۱۲ پیام** → صفحهٔ امتیاز.
- **اعتراف‌های seed:** ۲۳ متن دست‌نویس فارسی به اسم ghost ها در کانال اعتراف منتشر می‌شه (اگه کمتر از ۱۰ اعتراف موجود باشه).
- ادمین هم می‌تونه دستی ۳ تا ghost به صف اضافه کنه.
- قابل خاموشی با `COLD_START_ENABLED=false`.

## ۸. نوتیفیکیشن هوشمند و Retention

- **موتور:** هر ۳۰ دقیقه اسکن، سقف ۴۰ فراخوانی LLM در هر چرخه، سکوت شب ۰۱:۰۰-۰۶:۰۰.
- **سقف سخت فرستنده:** حداکثر ۲ نوتیف در روز، حداقل ۸ ساعت فاصله، بدون تکرار نوع در همان روز، ۳ بار dismiss = توقف ۷ روزه.
- **۵ استایل دولینگویی:** encouragement, social_proof, gentle_reminder, challenge, direct_invite — انتخاب بر اساس تاریخچهٔ dismiss و مدت غیبت.
- **تصمیم‌گیر LLM** (مدل sidecar، حداکثر ۲۰۰ توکن): قبلش prefilter (اشتراک‌دار، سرد، تازه فعال، کمتر از ۲ نوتیف در ۲۴ ساعت حذف)؛ خروجی JSON یا fallback به template. هرگز سیگنال اجتماعی اختراع نکن.
- **سیگنال‌های واقعی:** بازدید پروفایل از ghost ها، اندازهٔ صف مچینگ، ریتینگ بالا، محبوبیت.
- **تخفیف خودکار:** کد `ASHENA-XXXX-XXXX` تک‌مصرفه ۱۰-۲۰٪ وقتی LLM تصمیم بگیره؛ مدل‌ها: درصدی/مبلغی اشتراک یا هدیه سکه.
- **Churn prevention:** هر ۱۲ ساعت — یادآوری تمدید برای اشتراک‌دارانی که تا ۲۴ ساعت منقضی می‌شن؛ کد تخفیف ۱۰٪/۷۲ ساعته برای کسانی که ۱-۲ روز پیز اشتراکشون تموم شده (هر ۷ روز یکبار).

## ۹. ماشین XState (مهاجرت نیمه‌کاره)

- ماشین v5 با ۱۱ صحنه (onboarding, chat, search, rating, confession, browse, payment, support, admin, ...) و ~۴۰ event تایپ‌شده؛ snapshot در `ashena:sm:{uid}` با TTL ۷ روزه.
- **وضعیت: موازی/سایه** — هندلرهای legacy هر قدم رو fire-and-forget به ماشین آینه می‌زنن؛ dispatch هنوز با loc/step قدیمی اداره می‌شه («بعد از دورهٔ اعتبارسنجی سوییچ می‌کنیم»).
- **Input Interceptor فعال productionیه:** هر ورودی کاربر اول طبقه‌بندی می‌شه (متن/عکس/callback) و با جدول ALLOWED_INPUTS مسیرهای loc.step چک می‌شه — جلوی «تپ دکمه به‌عنوان متن» (ثبت اعتراف/تیکت از روی تپ کیبورد) رو می‌گیره. ولیدیشن اسم/سن/اعتراف/کد تخفیف هم همین‌جاست.
- نتیجه: معماری دو-سیستمی موقت — یکی از مهم‌ترین منابع پیچیدگی فعلی کد.

## ۱۳. نقاط قوت

1. **لایه‌بندی state بسیار مقاوم:** Mongo truth + Redis cache + reconcile در هر پیام + pendingRate + ack — درس‌های باگ‌های واقعی (ریست Redis، بلاک mid-chat، ریپلای) مستند و تست‌شده‌اند.
2. **ایمنی تراکنش مالی:** قفل SETNX + CAS مونگو + rollback کامل در مچ ناقص؛ سه مسیر تایید پرداخت؛ لاگ کامل.
3. **تمام قیمت‌ها داینامیک** (AdminConfig در Redis) — قیمت‌گذاری بدون deploy.
4. **AI harness پیشرفته:** human-layer با drives/mood/open-loops، سه حالت tool-calling با تشخیص خودکار، کنترل هزینهٔ همزمانی، paywall رفتارمحور.
5. **کولد-استارت تطبیقی** — مشکل واقعی محصولات مچینگ (شبکهٔ خالی) با راه‌حل عملی.
6. **E2E روی تلگرام واقعی** — چیزی که اکثر بات‌ها ندارن.
7. **ماژولار بودن پلتفرم:** افزودن بات جدید = یک فایل BotDefinition + رجیستری.
8. **منوی داینامیک DB-محور** + input interceptor تایپ‌شده.

## ۱۴. ضعف‌ها و بدهی فنی

1. **دو سیستم موازی:** legacy `src/handlers|models|keyboards` (عملاً مرده ولی هست) + machine XState سایه که هنوز dispatch نمی‌کنه — هزینهٔ شناختی بالا.
2. **دو سیستم لایک موازی** (Redis vs Mongo) با قیمت‌های متفاوت — باگ ریشه‌ای.
3. **دو کلاینت Redis** (`src/config.ts` و `core/database.ts`).
4. **اشتراک واقعی‌پرداخت شاید فعال نشود** — شاخهٔ `sub_` در مسیر callback مرده (بخش ۵.۶).
5. **callback server خام** (node:http با پارس رشته) — الان Express هست ولی callback-server.ts قدیمی باقیه.
6. **دوک ربات long-polling** — برای scale بعدی باید webhook بشه.
7. **داده‌های ghost خراب** (اسامی چینی/غلط‌اطلس) — تست‌های browse ازش رنج می‌برن.
8. **نویز هشدار امنیتی:** رمز عู่/توکن/IP در مستندات عمومی ریپو.
9. **پیچیدگی توزیع‌شدهٔ state:** Redis loc/step + ChatSession + sm:{uid} + pendingRate + gen — سه منبع state همزمان، حتی با reconcile هم مستعد race.

## ۱۵. نکات اخلاقی/ریسک حقوقی (برای تصمیم صدبات)

این بخش مستندسازیِ رفتار موجود کد است، نه پیشنهاد اجرا:

1. **فریب هویتی:** پرامپت پرسوناهای AI صریحاً دستور می‌ده هوش مصنوعی بودن را انکار کنن و خاطرات دروغین خلق کنن. این با قوانین تلگرام (سیاست اسپم/فروش‌های گمراه‌کننده)، انتظارات حریم خصوصی و در بسیاری حوزه‌ها قوانین مصرف‌کننده در تضاد بالقوه است. اگه صدبات چنین لایه‌ای بخواد، حداقل باید disclosure صریح («با یک دستیار هوشمند چت می‌کنید») در نظر بگیره.
2. **مونتایز وابستگی عاطفی:** پرامپت عمداً «وابستگی روانی» و قیمت‌گذاری لحظه‌ای عاطفی (smart-paywall در peak عاشقانه) رو هدف می‌گیره. ریسک شهرتی/حقوقی جدی داره.
3. **کاربر فِیک و بازدید جعلی:** ghost ها پروفایل جعلی‌اند و «۱ نفر داره پروفایلت رو می‌بینه» نشون می‌دن. رایج در صنعت ولی اگه فاش بشه، اعتماد صفر.
4. **محتوای جنسی‌محور در پرسوناها** (sexTemperament, libido drives) — برای ریسک محتوایی تلگرام حساس است.
5. **امنیت:** توکن/رمز در ریپو — اگه این ریپو مبنای صدبات شد، هیچ‌کدوم از این secrets رو کپی نکن.

## ۱۶. درس‌های قابل انتقال برای صدبات

اگه صدبات هم یک بات تلگرامی‌ست (چه دوستیابی، چه هر domain دیگه):

| ببر | نبر / اصلاح کن |
|---|---|
| الگوی state: Mongo truth + Redis loc/step + ensureSession reconcile + pending-before-clear | legacy code و دو-سیستمی — از روز اول یک مرجع state |
| الگوی قفل اتمیک (SETNX + CAS + rollback) برای هر اقدام پولی/مشترک | دو سیستم موازی (لایک، پرداخت، Redis client) |
| قیمت‌دینامیک از یک جدول واحد (config/DB) خوانده بشه — UI و کد از یک منبع | متن منو جدا از کد (فریب کاربر) |
| E2E با تلگرام واقعی + ریست امن کاربران تست | long-polling برای scale |
| ماشین state صریح از ابتدا (XState یا هر چیز) — نه مهاجرت موازی | کاربر فِیک بدون disclosure |
| AI: صف هر-کاربره + سقف همزمانی + paywall + اعتبارسنجی ابزار سمت سرور | پرسونای فریبکار بدون disclosure شفاف |
| سقف‌های سخت نوتیف (۲/روز، حداقل فاصله، احترام به dismiss) | secrets در مستندات عمومی |
