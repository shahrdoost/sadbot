## منوی home (رنگی، عین kpkchat)

کیبوردهای reply با فیلد `style` (Bot API 7.11+ — `primary` آبی برند / `success` سبز) ساخته میشوند؛ مثل kpkchat:

```
[🔗 به یک ناشناس وصلم کن]   ← primary (آبی)
[💘 مرور پروفایل‌ها]         ← success (سبز)
[📖 راهنما] [💰 سکه] [👤 پروفایل من]
[🎁 ماموریت‌ها] [💌 اعتراف ناشناس]
[🤖 چت با دستیار] [📩 پشتیبانی]
```

> ردیف آخر با `ai_enabled=0` به «[📩 پشتیبانی]» تنها تبدیل می‌شود — دکمهٔ دستیار از منو حذف می‌شود، نه فقط غیرفعال.

- زیرمنوی «وصلم کن»: `[🔗 غریبه ← primary]` / `[🚺 جستجوی دختر] [🚹 جستجوی پسر]` / `[🔍 جستجوی پیشرفته]` / `[🏠 منوی اصلی]`
- «🔍 جستجوی ویژه» و «👥 جستجوی کاربران» (home): ویزارد فیلتر در **حالت browse** — رایگان و بدون جستجوی زمان‌دار → دکهٔ فیلترشده (مرور پروفایل‌ها با جنسیت/استان/شهر/سن/علایق). مسیر «جستجوی پیشرفته» همان ویزارد ولی با جستجوی زمان‌دار پولی است (`search_advanced_any`/`search_advanced_gender` + `timeout_sec` از prices).
- ویزارد پیشرفته (۲۰۲۶-۱۰-۱۸ بازنویسی شد): مراحل `adv_gender → adv_province → adv_city → adv_age → adv_interests → adv_confirm` — انتخاب استان با کیبورد ۳۱تایی دوتایی (عین kpkchat)، شهرهای همان استان + «همه شهرها»؛ فیلتر استان در `BrowseFilter.ProvinceFilter` و `filtersCompatible` مچر هم اعمال میشود.
- لیبل دکمهها به `isHomeButtonText` + `handleHome` وصلند؛ تغییر نام دکمه = به‌روزرسانی هر دو + تست ناوبری.

### گارد ناوبری مرکزی

کیبورد home در صحنه‌های inline-only (browse) یا صحنه‌های متنی (search/ai/confess/support) میماند؛ در `HandleMessage` یک گارد مرکزی هر لیبل `isHomeButtonText` را در این پنج صحنه به home برمیگرداند (وگرنه داخل confess متن دکمه به‌عنوان متن اعتراف بلعیده میشد — باگ live رفعشده).

**فرار از promptهای ویرایش و ویزارد جستجو (۲۰۲۶-۱۰-۲۶، رفع باگ‌های live):**
- **promptهای ویرایش پروفایل** (صحنهٔ setup): لیبل home نباید به‌عنوان ورودی فیلد بلعیده شود — داخل prompt نام، کاربر عملاً به نامِ برچسب دکمه تغییرنام میداد؛ داخل سن/جنسیت/مکان کاربر در prompt گیر میکرد («یک عدد بین ۱۸ تا ۷۰ انتخاب کن»). حالا در `handleSetup` گارد مرکزی هر لیبل home را در حالت edit (یا پروفایل کامل) خارج میکند؛ `withHomeRow` یک ردیف «🏠 منوی اصلی» به کیبورد مراحل ویرایش اضافه میکند تا راه فرار داشته باشند. سکه قبلاً خرج شده، کول‌داون ثبت نمیشود.
- **ویزارد جستجوی پیشرفته** (`adv_*` در صحنهٔ home): مراحل ویزارد هر متن ناشناس را «ورودی فیلتر نامعتبر» میبلعیدند — لیبل‌های home گیر میافتادند. حالا در `handleHome` لیبل home از ویزارد خارج میشود.

تست: `nav_matrix_test.go` (`TestHomeNavFromEveryScene`, `TestHomeNavFromInlineOnlyScenes`, `TestHomeMenuColoredButtons`, `TestHomeNavFromAdvSearchWizard`, `TestHomeNavFromEditPrompts` — دومی قفل‌کنندهٔ باگ rename-با-لیبل است).

**فرار چت + منوی ☰ کت (۲۰۲۶-۱۱-۱۱):** کیبورد صحنهٔ چت (`chatRows`) حالا «🏠 منوی اصلی» دارد (مثل `ratingRows`) — زدن آن چت را مثل «🛑 قطع مکالمه» تمام و به ریتینگ می‌برد و **هرگز به مخاطب رله نمی‌شود** (`handleChat` می‌گیردش). ریشه: روی کت فقط همان دو دکمهٔ چت دیده می‌شد و راهی به منوی اصلی نبود («فریز»). لیبل‌های منو از `setMyCommands` (۱۲ فرمان، ثبت در startPlatform) و `resolveCommand` (`/cmd@bot` → لیبل home) هم کار میکنند؛ scope فرمان در کت پشتیبانی نمیشود (`BOT_COMMAND_SCOPE_UNSUPPORTED`) — لیست فقط global است.

## ماشین وضعیت

state در `bot_end_users.state` (JSONB): `scene` + `step` + `data`.

```
/setup: setname → setage → setprovince → setcity → setgender → (عکس اختیاری) → home
/home: وصلم کن → زیرمنو → غریبه/دختر/پسر → search (صف + هزینه)
/search: مچ → chat | ❌ لغو (بازگشت هزینه) | timeout (بازگشت هزینه)
/chat: 🛑 قطع / 🚫 بلاک / 🏠 منوی اصلی / پیام ناموفق → rating → ⭐..⭐⭐⭐⭐⭐ → home
/home: مرور پروفایل‌ها → browse (دکه inline: لایک/سوپرلایک/چت مستقیم/بعدی)
        مچ دوطرفه (لایک متقابل یا سوپرلایک یا چت مستقیم) → chat
/home: جستجوی ویژه/کاربران → ویزارد فیلتر (browse mode: جنسیت/استان/شهر/سن/علایق) → browse فیلترشده
/home: جستجوی پیشرفته → ویزارد فیلتر (timed mode) → search زمان‌دار (timeout از prices)
```

قوانین reconcile (مثل kpkchat):
- هر پیام اول `scene` فعلی را چک میکند؛ scene ناشناس → home.
- profile در `chatting` + `/start` → force-end با pending rate برای هر دو.
- وضعیت ماندگار (status/partner) در جدول‌های dating است؛ scene فقط ناوبری UI است.

## Onboarding (متون عین kpkchat)

| مرحله | متن | کیبورد |
|---|---|---|
| setname | `سلام! 👋\nاسمت چیه؟` | متن آزاد (حداقل ۲ حرف) |
| setage | `خوش اومدی {name}! 🎉\nچند سالته؟` | دکمه‌های ۱۸ تا ۷۰ |
| setprovince | `تو کدوم استان زندگی میکنی؟` | ۳۱ استان (`dating/iran.go` عین kpkchat) |
| setcity | `استان {province} انتخاب شد.\nتو کدوم شهر هستی؟` | شهرهای همان استان |
| setgender | `دختری یا پسری؟` | هوشمند سن: ≤۳۰ «خانومم/آقام»، >۳۰ «خانوم/آقا» |
| عکس (اختیاری) | دعوت به آپلود آواتار | «⏭ رد شد» / عکس (پاداش یکباره) |
| پایان | خوش‌آمد + منوی home | منوی رنگی |

استان/شهر با `+bonus` signup (سکهٔ ثبت‌نام از `prices.signup_bonus`)؛ referral با payload `ref_<id>` در `/start` هر دو طرف را شارژ میکند.

## سرچ و مچینگ

**شروع**: چک بلاک ادمین → چک وضعیت → کسر هزینهٔ جنسیت (`search_stranger_*` / `search_gender_*`؛ مشترکین رایگان) → CAS `joined→searching` + ثبت فیلتر در `dating_search_requests`. متن انتظار مثل kpkchat؛ لغو و timeout هزینه را برمیگردانند.

**مچر** (هر ۵ ثانیه، هر باتِ datingِ running):
1. بارگذاری searchers با `FOR UPDATE SKIP LOCKED`.
2. جفت‌گیری حریصانه با `similarityScore` (وزن‌های kpkchat: جنسیت ۱۰/۵، شهر ۸، استان ۴، سن ۵/۲، هر علاقهٔ مشترک ۳).
3. فیلتر جنسیت/شهر/بازهٔ سن هر دو طرف (جستجوی پیشرفته `filtersCompatible`).
4. `ClaimMatch` اتمیک → scene هر دو `chat` + اطلاع «وصلت انجام شد!».
5. **گوست‌ها** (پیش‌فرض **خاموش** — `ghost_enabled=0` در prices، فعال‌سازی per-bot): کاربران نمونهٔ `is_ghost` در همان صف شرکت میکنند؛ چت با گوست با پرسونای LLM ساخته‌شده از پروفایل خودش (فارسی محاوره‌ای، حباب‌های کوتاه، تأخیر تایپینگ، گارد شکستن شخصیت؛ fallback اسکریپتی بدون LLM) ادامه مییابد و **بدون صفحهٔ امتیازدهی** تمام میشود. با خاموش‌بودن گوست، جستجوگر تنها در جستجو میماند (بدون جایگزین AI).
6. **timeout**: از `filters.timeout_sec` (پیشفرض ۴۰s؛ جستجوی پیشرفته ۱۸۰s)؛ لغو + بازگشت هزینه + نوتیفیکیشن.

## Browse (سبک Tinder)

- **کارت** (۲۰۲۶-۱۰-۱۸ بازطراحی شد، عین kpkchat): کپشن فشرده — `💕 نام 👩` / `🎂 سن ساله` / `📍 شهر، استان` / `⭐ امتیاز` / `🎯 علایق · جداشده` (سقف ۵) / خط پایانی سکه (رایگان باقی‌مانده / هزینه / پریموم). عکس با `SendPhotoKBD`، وگرنه متن؛ دکمه‌ها: لایک (سقف رایگان روزانه `browse_free_likes` بعد `browse_like_cost`)، سوپرلایک (`superlike_cost` + سقف روزانه + نوتیفیکیشن ویژه)، چت مستقیم (`direct_chat_cost`؛ مشترکین رایگان)، بعدی، منوی اصلی.
- **جایگزینی صفحه‌ها (replace-view)**: dating با `ReplaceViews()` روی قابلیت engine روشن است — هر صفحه (کیبورد/کارت) پیامِ قبلی را **فقط بعد از فرودِ جایگزین** حذف میکند (send-then-delete)؛ اگر ارسال جدید خطا بدهد صفحهٔ قبلی سر جایش میماند («پیام پاک میشه و هیچی نمیاد» رفع شد). کارت browse هم با همان viewDrop جایگزین میشود (`browse_card_msg` در state؛ حذف اضافهٔ کارت legacy فقط بعد از فرود کارت بعدی). `keepCardNote` کارت را به اعلان تبدیل و از tracking خارج میکند (پیام میماند).
- **fallback عکس کارت**: عکس پروفایل با file_id همان پلتفرم ارسال میشود؛ file_id تلگرام روی کت (`FILE_ID_INVALID`) یا هر خطای دیگری → کارت **متنی** جایگزین میشود — هرگز چت خالی نمیماند (`TestPhotoFailureFallsBackToTextCard`).
- لایک/سوپرلایک متقابل → connect؛ رد (`kind=pass`) تا تکرار کارت ثبت میشود.
- **مرور فیلترشده** («جستجوی ویژه/کاربران»): `BrowseCandidatesFiltered` با جنسیت/استان/شهر/سن/علایق از ویزارد؛ رایگان؛ فیلترها با خروج/خالی شدن دکه پاک میشوند.

## اقتصاد سکه

- کیف پول (`💰 سکه`): موجودی + روشهای کسب + پکیج‌ها (درگاه catroom.ir سازگار Zibal؛ `PAYMENT_DEV_MODE` برای تست فوری) + اشتراک ۳۰ روزه.
- ماموریت‌ها (`🎁 ماموریت‌ها`): عضویت کانال(ها) با تایید سروری (`+bonus`) — چندکاناله از `prices.channels`؛ لینک دعوت (`+bonus` دوطرفه). **لینک کانال per-platform است** (`channelLinkFor`: روی کت `t.me/X` → `https://cr0.ir/X`، تلگرام دست‌نخورده). **روی کت استعلام عضویت انجام نمیشود** (`getChatMember` METHOD_NOT_FOUND) — زدن «✅ بررسی عضویت کانال» عضویت را قبول و پاداش را میدهد؛ تلگرام استعلام واقعی دارد (`TestChannelMissionKatTrustsTap`).
- سوییپر پرداخت: auto-verify هر ۱ دقیقه (۱۵ دقیقه اول) + انقضای pending بعد از آن (**فقط یک بار** اطلاع‌رسانی — رفع باگ اسپم «مهلت پرداخت تمام شد»)؛ انقضای اشتراک هر ۶ ساعت.
- تخفیف (`discount_codes`) و بوست پروفایل (`growth.go`).

## پروفایل من (پورت «حساب من» kpkchat)

صفحهٔ inline غنی (نام/جنسیت/سن/استان/شهر/علایق/امتیاز/عکس/سکه/اشتراک) + ۶ ویرایش: نام (هزینه + کول‌داون)، سن/جنسیت/مکان/عکس (`edit_cost` + کول‌داون هفتگی مشترک؛ اولین تغییر هر فیلد رایگان)، علاقه‌مندی‌ها (رایگان، حداکثر ۵ تا از ۱۵ گزینه). prompt عکس با گارد home فرار میکند بدون ثبت کول‌داون. **حذف حساب**: ۳ سکه + soft-deactivate (`dating_profiles.deactivated_at` — migration 0014)؛ کاربر غیرفعال از دکهٔ مرور و مچ حذف میشود.

## اعتراف و پشتیبانی

- **اعتراف ناشناس**: متن ≥۵ حرف → پیش‌نمایش → تایید (`confess_cost`) → ثبت برای تایید ادمین (پنل) → انتشار در کانال + اطلاع به کاربر. کاربران نمونه هم اعتراف تولید میکنند (seed).
- **پشتیبانی (گفتگوی تیکتی، ۲۰۲۶-۱۱-۱۶)**: متن ≥۳ حرف → تیکت (پنل). پاسخ ادمین از پنل به چت کاربر می‌رود و **دو دکمهٔ inline** همراه دارد: «✍️ ادامهٔ گفتگو» (`act:support:continue:<id>`) و «🔒 بستن تیکت» (`act:support:close:<id>`). کاربر پاسخش را داخل همان تیکت می‌نویسد (تیکت از `answered` به `open` برمی‌گردد و در صف ادمین می‌نشیند) یا تیکت را می‌بندد. با تیکت باز، زدن «📩 پشتیبانی» پیام را به همان تیکت اضافه می‌کند و فقط «📝 تیکت جدید» (`act:support:new`) تیکت تازه می‌سازد; دکمهٔ کهنه روی تیکت بسته رد می‌شود. هر نوبت گفتگو در `support_ticket_messages` ثبت می‌شود (migration 0015) و پنل کل رشته را نشان می‌دهد. **فقط متن تایپ‌شده تیکت می‌شود** — پرس دکمه هرگز بدنهٔ تیکت نیست (`bc.IsCallback` گارد می‌کند). ریشه: کت هر پرس کیبورد را callback با `data` = برچسب می‌فرستد، پس دکمهٔ یک صفحهٔ قدیمی (مثل «📞 پشتیبانی» یا «👤 مشخصات من») مستقیم به‌عنوان متن تیکت ذخیره می‌شد و صندوق ادمین از برچسب پر می‌شد نه از پیام کاربر.
- **عکس و صف بین‌پلتفرمی (۲۰۲۶-۱۱-۱۶)**: مچ تلگرام↔کت واقعاً انجام می‌شود (`Searchers` فیلتر پلتفرم ندارد؛ با اکانت MTProto و کاربر واقعی کت تأیید شد). کت `forwardMessage` ندارد و file_id تلگرام را حل نمی‌کند، پس **فوروارد هرگز استفاده نمی‌شود**: `relayCrossPlatformPhoto` بایت‌ها را از سمت فرستنده می‌خواند (`PhotoFetcher` → `DownloadFileByFileID`، ۳ تلاش کوتاه) و روی سمت گیرنده به‌صورت `sendPhoto` آپلود می‌کند. شاخهٔ عکس **قبل از** تلاش فوروارد می‌آید — وگرنه فورواردی که روی کت همیشه fail است، پیام degrade می‌داد و عکس هرگز نمی‌رسید. عکس رله‌شده حالا ردیف **آینهٔ outbound** هم می‌گیرد، وگرنه ستون «ارسالی» فید پنل برای همهٔ عکس‌ها `—` می‌ماند.
- **صف تلاش مجدد ماندگار**: هر ارسال ناموفق (متن/عکس/اعلان مچ) در `outbound_retries` (migration 0016) پارک می‌شود، نه در صف حافظه‌ای — چون ری‌استارت همان چیزی است که قطعیِ یک سمت شبیه آن است. `DurableQueue` هر ۵ ثانیه ردیف‌های `next_at <= now() AND attempts < 5` را می‌خواند، با backoff ۵→۱۲۰ ثانیه تلاش می‌کند و در موفقیت حذف می‌کند. `Fail` در آخرین تلاش ردیف را DELETE می‌کند (اگر فقط reschedule شود، چون `Due` سقف را نمی‌خواند، برای همیشه می‌ماند). فقط 403 حذف فوری است.
- **رسانه‌های دیگر**: استیکر/ویدیو/ویس/فایل روی کت متد ارسال ندارند → پیام «فقط عکس و متن منتقل میشه…» و **چت زنده می‌ماند** (`TestCrossPlatformMediaDegrades` با Voice تست می‌شود، نه Photo).

## دستیار هوشمند (`🤖 چت با دستیار`)

quota رایگان (`ai_free_messages`) بعد هر پیام `ai_message_cost` (مشترکین نامحدود)؛ gate از `prices.ai_enabled` (پنل میتواند قطع کند)؛ شخصیت بر اساس جنسیت؛ تاریخچه محدود در state.

**دکمهٔ منو هم با همان کلید برداشته می‌شود (۲۰۲۶-۱۱-۱۳):** `ai_enabled=0` علاوه بر بستن صحنه، «🤖 چت با دستیار» را از کیبورد home حذف می‌کند (`homeKBFor` / `homeKBForEnabled`). همهٔ صفحه‌هایی که منوی home را رندر می‌کنند از `homeKBFor(bc)` استفاده می‌کنند، و اعلان timeout جستجو در مچر از `homeKBForEnabled(aiOn(prices))` — چون BotContext ندارد. لیبل ثابت `assistantLabel` است؛ تغییر نام دکمه = به‌روزرسانی همان ثابت. پرس دکمهٔ کهنه (یا `☰ /ai`) با پیام «غیرفعال است» به home برمی‌گردد. ورودی `/ai` در منوی ☰ پلتفرم می‌ماند چون `BotCommands()` به تنظیمات بات دسترسی ندارد (و scope در کت پشتیبانی نمی‌شود) — ولی همان پیام غیرفعال را می‌دهد. تست: `TestAssistantHiddenFromHomeWhenDisabled`.

**وضعیت دیپلوی (۲۰۲۶-۱۱-۱۳):** تنظیمات production @ashnadbot روی `ai_enabled=0` است (هم تلگرام، هم دوقلوی کت @ashna_bot — یک بات/یک تنظیم) و کد روی سرور دیپلوی شده. راستی‌آزمایی زنده با اکانت MTProto پنل: `/start` روی @ashnadbot → ردیف آخر کیبورد فقط «📩 پشتیبانی» است و دکمهٔ دستیار در منو نیست. دوقلوی کت همان باینری/همان قالب/همان تنظیم را اجرا می‌کند (`[runtime] bot آشنا (@@ashnadbot) running on kat`).

**پاسخ تأخیری مقید به صحنه (۲۰۲۶-۱۱-۱۳):** پاسخ دستیار با تأخیر ۰.۷–۲.۵ ثانیه («تایپینگ انسانی») فرستاده می‌شود و همین‌طور حباب‌های گوست با تأخیر چندثانیه‌ای. هر دو حالا پیش از ارسال با `BotContext.SendIfStillInScene` / `StillInScene` صحنهٔ **ذخیره‌شده** را دوباره می‌خوانند: اگر کاربر در این فاصله از صحنه خارج شده باشد (منوی اصلی/جستجو/اکانت) پیام دور ریخته می‌شود. ریشه: پاسخ دیررس روی منوی اصلی می‌نشست و حس «چت هنوز ادامه دارد» می‌داد. گارد در engine است نه در قالب، پس هر تمپلیتی که ارسال تأخیری دارد از همین الگو استفاده کند. تست: `scene_guard_test.go`.

## پنل مدیریت (AdminOps)

از پنل وب per-bot: تنظیمات عددی (۳۹ فیلد — spec قالب دوست‌یابی؛ فرم «تنظیمات» هر بات از spec **قالب خودش** می‌آید نه لیست سراسری)، ویرایش کانالها، هارنس AI (لیست کاربران mid-AI + toggle)، چت‌ویور و فید پیامها، برادکست (متن + عکس + فوتر)، کدهای تخفیف، اعترافها/تیکتها، اسکن بلاک تلگرامی، ریست/مسدود/سکه/پیام مستقیم per-user.

**فید چت — یک سطر برای هر پیام**: فید جهانی پنل هر پیام صحنهٔ chat را **یک بار** نشان می‌دهد (رویداد inbound فرستنده) و در همان سطر گیرنده را کنار فرستنده می‌آورد: `دریافتی: امیر - ارسالی: نگار`. گیرنده از **آینهٔ outbound** (`RecordOutboundForPartner`) با `LEFT JOIN LATERAL` پیدا می‌شود، نه از `dating_profiles.partner_user_id`: پایان چت، `partner_user_id` را روی هر دو پروفایل پاک می‌کند، پس پروفایل گیرندهٔ همهٔ پیام‌های گذشته را خالی می‌گذاشت (باگ پروداکشن — همهٔ ۱۹۱ پروفایل NULL بودند). آینه خودش در فید خوانده نمی‌شود، وگرنه هر پیام دو بار می‌آمد. عکس‌ها هم آینه می‌گیرند تا ستون «ارسالی» برایشان `—` نماند. `chat_surveillance_test.go` عمداً چت را قبل از خواندن فید تمام می‌کند تا همین حالت پروداکشن را بازتولید کند.

## E2E زنده

با اکانت MTProto پنل (`tgsidecar`) میتوان بات را مثل یک کاربر واقعی چت کرد: پیام متنی دکمهها را بفرست (کیبورد reply = متن). درایور: `docker exec -i -e PYTHONPATH=/app sadbot-tgsidecar python3 -` با `get_client("<sidecar_account_id>")`. **دکمه‌های inline هم قابل فشردن هستند** — شیء دکمهٔ Telethon در این wrapper متد `click()` ندارد؛ callback data در `btn.type.data` است و باید درخواست خام بزنید:

```python
from telethon import functions
await client(functions.messages.GetBotCallbackAnswerRequest(
    peer=entity, msg_id=card.id, data=b"act:browse:next"))
```

نکته: کارت‌های قدیمی در history می‌مانند — هنگام تست حتماً کارت *جدید* را از `iter_messages` بگیرید ( آخرین پیامِ دارای `reply_markup` ) وگرنه کارت کهنهٔ ویرایش‌نشده را می‌بینید.

**هارنس E2E آماده** (`deploy/e2e/`): اسکریپت‌های پایتونی که داخل کانتینر `sadbot-tgsidecar` با `python3 -` پایپ میشوند — `explore_bots.py` (کاوشگر دکمه‌ها: هر دکمه را میفشارد و پاسخ را جمع میکند، خرید/برداشت را skip میکند)، `flow_dating.py` (جریان کامل دیتینگ)، `flow_duel.py` (یک راند کامل duel)، `live_cross_platform.py` (مچ و رلهٔ متن+عکس بین تلگرام و کت با اکانت واقعی)، `harness.py` (درایور مشترک BotDriver). جزئیات اجرا در [DEPLOYMENT.md](./DEPLOYMENT.md).
